# GQ-011 — AI slop pattern review
Status: implemented
PRD link: GQ-011

Goal: give a developer a concrete, source-backed design/code critique of one authorized local or public live page without claiming to identify its author.
Inputs and types: selected review mode, local fixture or public live URL, masked screenshot, and bounded same-origin HTML/CSS/JS response text delivered to the run's Chromium page.
Outputs and types: a review story with at least six distinct observations, or `insufficient evidence`; each observation has a category, visible/source signal, why, avoid, change, and GitHub skill link.
Pattern coverage: retain the current eight signals and add source-backed Impeccable catalog cues for decorative surface treatments, typography defaults, repeated or accented cards, ornamental motion, and stock headline/copy. Each cue needs a distinct source condition and fixed, non-sensitive evidence text. Judgment-only catalog items and browser geometry checks remain outside the automatic source scan.
Expanded design coverage: inspect component nesting, decorative grids, hero badges, type hierarchy and capitalization, display headline scale, background halos and warm palette defaults, numbered labels, elastic motion, formulaic contrast copy, dismissive buzzwords, and placeholder imagery only when delivered markup or CSS supports each observation. One source condition must not generate several equivalent findings; intentional uses remain review prompts, never authorship claims.
Sensitivity calibration: recognize equivalent authored forms such as `rem` display sizes, animation shorthand in either order, uppercase text from CSS, and nested semantic cards. Keep the six-distinct-finding threshold, and require observations from three independent areas before showing the stamp so one decorative treatment cannot manufacture a story. Each finding remains a review prompt even after the story threshold.
Preconditions: ordinary URL policy and one-run admission pass. Public live URLs require `ALLOW_LIVE_SITES=true`. Review mode uses one navigation and no model call.
Invariants / security: one exact origin, one Chromium, ten-action and 60-second limits, no cross-origin fetch, no non-GET/HEAD requests in live review, no arbitrary page JavaScript evaluation by GhostQA, no source text or credentials sent to the client. The stamp is a UI overlay on the masked screenshot. It is not embedded in bug evidence. Patterns cannot establish AI authorship. The six-observation threshold cannot be padded with generic advice.
Happy-path example: the synthetic `/slop` fixture contains at least six independently detectable design/code patterns; the UI shows a stamped preview and six or more evidence-backed story entries.
Failure-path example: `/health` has fewer than six patterns and shows `insufficient evidence` with no stamp.
Acceptance criteria (Given/When/Then): Given review mode and `/slop`, when the run ends, then the story contains at least six distinct supported entries with why/avoid/change/skill fields and the masked preview displays a stamp animation. Given `/health`, then no `AI SLOP` stamp or story is shown. Given a reduced-motion preference, then the stamp remains visible without animation. Given a functional test run, then existing verified and no-finding semantics remain unchanged.
Given explicit live mode and a public URL, when review mode starts, then it is admitted using the existing public URL policy and captures only same-origin delivered source. Non-GET/HEAD requests initiated by the page and cross-origin requests are blocked. Given live mode disabled or a private/internal URL, then a public/private review URL respectively is rejected before launching Chromium.
Given delivered markup and styles with several catalog patterns, when reviewed, then the story includes their distinct catalog names and links to relevant commands in the Impeccable GitHub skill. Given only prose describing those patterns, then no source-style findings are fabricated. Preserve the six-supported-observation threshold and author-attribution disclaimer.
Given delivered HTML/CSS containing the expanded component, text, background, card, motion, and imagery patterns, when reviewed, then each new cue has a distinct ID, fixed evidence, a concrete change, and a matching GitHub skill. Given commented-out examples or a single isolated cue, then no six-finding story appears.
Given six or more signals only from one decorative area, when reviewed, then the result is insufficient evidence. Given six or more signals spanning three design/code areas, then the story appears. Equivalent source forms should match the same cue ID without adding duplicate findings.
Unit test names: `tests/slop-review.test.ts` checks pattern detection, distinctness, threshold, and safe output.
Integration/E2E test names: `tests/e2e/demo.spec.ts` checks review mode, stamp, insufficient evidence, and existing functional flow.
Out of scope: author attribution, whole-repository analysis, cross-origin assets, fetched source maps, auto-fixing, crawling beyond the submitted origin, and generated repro tests for design observations.

## Design-first verdict (approved 2026-11-02)
Problem: findings came only from source-text regexes, so the review graded how the code was written against a guideline catalog instead of how the rendered page actually looks.
Inputs: one CDP `DOMSnapshot.captureSnapshot` of the rendered page with a fixed list of computed style properties and layout bounds, the viewport size, and the existing delivered same-origin sources. CDP snapshot does not run page JavaScript. Page text is used only for counts and lengths; it is never copied into output.
Outputs: `DesignReview` = `{ verdict, designScore (0–100), confidence, designFindings[], patternReview (existing SlopReview), supportingCues[] }`. Each design finding has an id, aspect (`color`, `surface`, `layout`, `type`, `composition`), title, measured rendered evidence (numbers, computed values; no page text), why, change, weight, strength (`strong`/`weak`), GitHub skill, and `supportedBy` = titles of matched guideline cues.
Rendered signals: violet-blue gradient canvas (strong 25), other large gradient canvas (weak 12), glass blur surfaces (strong 15), uniform card set of at least three same-size/same-radius/same-shadow surfaces (strong 20), one large radius on most surfaces (weak 10), one soft shadow on most surfaces (weak 10), flat type scale (weak 10), single default font (weak 10), gradient text (strong 15), centered single-column stack (weak 10).
Verdict rules: fewer than three visible text elements, or no snapshot, => `insufficient-evidence`. Score >= 50 with >= 2 aspects and >= 1 strong signal => `ai-slop-design` (stamp; confidence `high` if the pattern review is also a story, else `medium`). Score >= 25 => `mixed`. Otherwise `ai-slop-pattern` when the pattern review is a story, else `distinct-design`. Patterns never stamp alone.
Invariants: the 35 guideline cues and the six-cue/three-area pattern rule stay unchanged and are shown as supporting detail. Matched guideline cues appear even when the pattern threshold is not met. No authorship claim. One navigation, no model call, same limits.
Failure modes: snapshot fails or times out => design `insufficient-evidence`, pattern cues still listed, no stamp. Hidden/zero-size nodes are ignored. `html`/`body` gradients count as the full viewport because their background paints the canvas.
Acceptance: Given `/slop`, the verdict is `ai-slop-design`, design findings come before guideline cues, and the stamp shows. Given `/health`, the verdict is `insufficient-evidence` with no stamp. Given a pattern story whose rendered page has no design signals, the verdict is `ai-slop-pattern` with no stamp. Given a plain page with three or more text elements and no signals, the verdict is `distinct-design`. Rendered evidence and output contain no page text.
Tests: `tests/design-audit.test.ts` (snapshot parsing, each signal, verdict rules, privacy); `tests/e2e/demo.spec.ts` (verdict, design-first story, stamp only for design verdict).
Evidence: RED `npx vitest run tests/design-audit.test.ts` failed when `src/lib/design-audit.ts` was absent, then caught a character-count tie-breaker bug in body font-size selection. GREEN `npm run check`, `npm run test` (12 files, 112 tests), and `npm run test:e2e` (6 browser tests) passed on 2026-11-02.
